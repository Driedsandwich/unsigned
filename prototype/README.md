# Unsigned — 動く試作

`index.html` をダブルクリックして Chrome で開いてください。サーバー、アカウント、ビルド、追加インストールは不要です。HTML・CSS・JavaScript はこの1枚に収まっています。

添付されたA3の3画面と指定仕様を基に作成しました。日本語の案内以外の製品画面は英語です。見本の人物・回答・主題・人数はすべて架空です。

## ファイル

- `index.html` — 単独で動く試作。
- `README.md` — 操作手順、検証結果、本番への置き換え箇所。
- `verify.cjs` — Node.js の標準機能だけで実行する状態遷移・UI配線の検証。HTMLを使うためには不要です。

外部ライブラリ、外部画像、Webフォントは読み込みません。Inter が端末にあれば使用し、なければ指定のシステムフォントへ切り替えます。コード内に通信処理はなく、CSPでも `connect-src 'none'` を指定しています。外部アプリへの書き込み・送信・公開はありません。

## 最短の試し方

1. 初期状態の **Respondent / Desktop / Yes** で、**Insert example** を押します。
2. 1秒待つと **On-device AI** が動き、さらに短い待ち時間の後、下書きが段階的に表示されます。
3. **Edit draft** で下書きを直し、**I approve this version** にチェックして **Send approved response** を押します。
4. 送信を模したJSONを確認し、**See themes in Admin** を押します。初期状態では隠れていた **Clearer handoffs** が表示され、3つの島になります。
5. **Draft next week’s question** の横にある実行場所を確認して **Use draft** を押します。**Questions** には「Draft only · Not scheduled」として置かれます。
6. **Settings → For AI agents** で道具一覧と非公開情報を確認します。

最初の2つの島だけを見たい場合は、手順1より前に **Admin** に切り替えてください。ページの再読み込みで全データを初期状態へ戻せます。

## 全8項目の受け入れ確認

### 1. 日本語の案内

- 最上部に指定された「これは試作です。何から押すか: …」の全文があります。
- この案内は `lang="ja"`。日本語用フォントを指定しています。
- 案内の下にも、架空の見本、AIの模擬動作、ページ内だけで動くことを表示しています。

### 2. 試作用の切り替え

- **Respondent / Admin** で回答者と運営の画面を切り替えます。
- **Mobile** はアプリ枠を最大390pxに、**Desktop** は最大1440pxにします。日本語の案内と試作用の操作帯は常に外側に残ります。
- 実際の窓が狭い場合は、Desktopを選んでも窓の幅に収まります。
- **This device has on-device AI: Yes / No** で端末の能力を模擬します。実際の端末能力を検出する処理ではありません。
- Yes / No を変更すると、未送信の入力・下書き・承認が消えます。この挙動は操作帯に記載しています。送信済みのレシートと主題の集計は保ちます。

### 3. 回答から承認まで

1. **Your words · Private** に文を入力します。見本を使う場合は **Handoffs / Focus time / Decision context** から選び、**Insert example** を押します。
2. 入力イベントごとに **Source vN** が増えます。最後の入力から1秒間止まるまで書き直しを開始しません。
3. 処理中は **On-device AI** と状態表示が変化し、下書きが少しずつ表示されます。完了後は **Ready to review** になります。OSの動きを減らす設定では点滅を止めます。
4. 処理の途中で違う文を入力してみてください。入力版と処理トークンの両方を確認し、古い処理結果を破棄します。完了していない下書きは承認できません。
5. **Edit draft** を押すと下書きを直接編集できます。編集を始めた時点で自動更新から保護されます。
6. 保護された状態で原文を変えると **Source changed** と表示され、下書きは上書きされません。承認はできなくなり、**Regenerate** を押した場合だけ新しい原文から作り直します。
7. 原文・下書きが空白のみのときも送信できません。入力と下書きは各1200文字までです。
8. **I approve this version** は初めは未チェックです。完了した下書きにチェックを付けると送信できます。原文または下書きを変えると、チェックと送信可能状態が直ちに解除されます。
9. 時の流れはデスクトップでは右側、モバイルでは下側に並びます。**Typed here · Private → Rewritten here · On device → Approved rewrite only · Sends** を確認してください。

見本の書き直しは3種類の固定文です。英語・日本語の一部の語に反応して選び、該当しない場合はハンドオフの文になります。任意の文章を意味どおりに書き直すAIや、匿名化の品質を評価する処理ではありません。

### 4. 送信後のJSON

送信はページ内の状態更新です。レシートには **What was sent / Simulated payload** と表示します。ハンドオフの見本を編集せずに送ると次の形になります。

```json
{
  "question_id": "check-in-001",
  "approved_rewrite": "Handoff notes are sometimes hard to find. A shared checklist could help."
}
```

- 本文を編集した場合は、承認した編集後の本文が入ります。前後の空白だけを除去します。
- 原文、編集履歴、参加者ID、実行場所などの余分なキーは入りません。
- 原文と編集中の下書きは送信後にアプリ状態と入力欄から外します。これはプロセスメモリの安全な消去を保証するものではありません。
- 同じ回答でSendを連打しても人数は増えません。
- **Next fictional respondent** で別の架空の参加者として新しい回答を試せます。この操作だけが試作用の参加者を増やします。

### 5. 端末AIがない場合

1. 未送信の状態で上部の **No** を選びます。
2. 原文入力と書き直し欄が消え、**This device can't rewrite privately** が表示されます。原文をクラウドに送る操作はありません。
3. **Clearer handoffs / Focus time / Decision context** の3択から選びます。
4. 短い定型文を選択して回答を完成させます。自由記入欄はありません。
5. 表示された回答を承認して送信します。JSONは同じ2キーだけです。主題への反映も同じです。
6. 選択肢や定型文を変えたら承認が解除されることを確認してください。

### 6. 運営の主題の地図と人数の境界

**Admin → Themes** に、プライバシーの帯、主題の地図、常設の **Below 3 people: hidden** の説明があります。

受け入れ確認用の初期データは次の通りです。これは架空データの設定表であり、運営UIに小人数の情報を表示するものではありません。

| 主題 | 初期の架空人数 | 初期表示 |
| --- | ---: | --- |
| Clearer handoffs | 2 | 島・名称・要約・人数を出さない |
| Focus time | 4 | 3–5 people |
| Decision context | 6 | 6–8 people |

- 初期状態は2つの島です。3つ目の予約枠や「残り1人」のような手掛かりは表示しません。
- 最初の回答者がハンドオフの見本を送ると、その主題が3人に達し、3つ目の島が初めて表示されます。
- 回答は承認済み本文の簡単な語の判定で1つの見本主題に入ります。固有の文面や新しい主題の生成はしません。
- 島には要約、Strength、Respondent band と帯を表示します。正確な人数は運営画面へ渡しません。
- Strength は見本の言及回数に基づく Medium / High で、感情の評価ではありません。人数の帯とは別の情報です。
- **Next fictional respondent** でハンドオフを合計4件送ると6–8、合計7件送ると9+になります。送信ボタンの連打や画面切り替えでは増えません。
- 点線は関連する話題を示し、人のつながりを示しません。
- アプリ枠が760px以下なら島は読み順の縦リストになり、線を省きます。狭い窓と拡大時のリフローに対応するCSSを用意しています。

### 7. 次週の問いの下書き

1. 最初にAdminへ入ると、表示可能な主題だけから問いの見本を作ります。
2. Yesで開始した処理は **Ran on device**、Noで開始した処理は **Ran in cloud (fallback)** と下書きの横に表示します。どちらも実AIではなく、このページ内の別々の見本関数です。
3. Yes / No を切り替えただけでは、すでにできた下書きの実行場所を付け替えません。**Next run** が次回の行き先を示します。
4. **Regenerate** を押すと、その時点の端末設定で実行し直し、新しい実行場所を表示します。処理途中に設定を変えても、その処理を開始した場所を保ちます。
5. 問いの本文は編集できます。空欄のままでは **Use draft** は押せません。
6. **Use draft** を押すと **Questions** に下書きとして採用します。**Draft only · Not scheduled** と表示し、予約・公開・回答者の現在の問いの差し替えは行いません。

### 8. AIエージェント向けの口

**Admin → Settings → For AI agents** に次の一覧があります。

| 道具 | 一覧に記載した契約 |
| --- | --- |
| `get_themes` | 集約した主題と人数の帯だけ。3人未満を除外 |
| `draft_check_in_question` | 表示可能な主題から問いの下書き。端末優先、端末AIなしなら雲 |
| `schedule_check_in` | 下書きとして置くだけ。予定・公開の確定には人が必要 |

生の回答、3人未満の主題の内容・人数、個人ごとの回答（承認済みを含む）は、口から出ない情報として明記しています。この試作は説明の一覧だけで、呼び出しボタン、API、エージェント接続は実装していません。

## 本番で Firebase AI Logic に置き換える箇所

以下は渡された要件に基づく接続設計です。Firebase AI Logic の現在のSDK名・メソッド・モデル・端末対応・オンデバイス推論の提供可否は、資料にないため **未確認** です。Web検索や外部資料の参照は行っていません。この試作にFirebase製品が実装済み・動作検証済みという意味ではありません。

HTML内の `Production boundary A` 〜 `D` が主な差し替え位置です。

| 箇所 | 現在の試作 | 本番で満たす必要があること |
| --- | --- | --- |
| A: `rewriteOnDeviceMock` | 原文の語から固定の中立文を選ぶ | **書き直しは端末だけ**。実際の端末能力・モデル準備・実行エラーを判定する。対応できない場合は選択式へ戻し、原文を雲へフォールバックしない。Firebase AI Logicでこの要件を実現できるかは未確認 |
| `setRaw` / `startRewrite` / `grow` / `regenerate` | 1秒の待機、模擬遅延、段階表示 | 実推論のキャンセル・遅延結果にも入力版と処理トークンの検査を残す。編集保護、明示再生成、承認解除を維持する |
| B: `submit` | 2キーのJSONをページ内に反映 | 許可した問いIDと承認済み本文だけを送る送信境界。原文や履歴をリクエスト・ログ・解析・エラー記録へ含めない。送信失敗・再試行・二重送信を扱う。本番の通信方式と認証方法は未確認 |
| C: `aggregateApprovedMock` / `publicThemes` | 架空人数と語の判定で見本主題を更新 | **束ねは雲だけ**。受け取るのは承認済み本文。異なる人の人数を確かめ、3人未満の主題・本文・正確な人数を返さない境界をサーバー側で実装する。モデルや集約処理の具体APIは未確認 |
| D: `runQuestionDraftMock` | Yesなら端末用、Noなら雲用の見本関数 | **問いの下書きは端末優先**。端末AIが使えない場合のみ雲へ。入力は公開可能な集約主題だけ。実際の処理経路に由来する実行場所を出力に添える。具体APIは未確認 |
| `generateQuestion` / `Use draft` | 問いをメモリ内で採用 | 本番の下書き保存先と人による確定フローに接続。生成・採用だけで予約や公開をしない |
| Settingsの道具一覧 | 説明のみ | 実際に提供する場合は認可、スキーマ、人数閾値、個人情報の除外、人の確定をAPI側でも強制する。具体的なエージェント接続方式は未確認 |

現在の「異なる人」は試作用のローカル識別子と架空の初期データで代用しています。識別子は送信JSONに含めません。本番で匿名性と重複防止を両立する方式は、この試作では実装・検証していません。

**Raw responses are never stored** は指定された製品画面の文言です。この試作では原文を入力中のDOMとJavaScriptメモリで一時的に扱い、データベース・ファイル・ブラウザストレージへ永続化しません。集計、承認済みレシート、問いの下書きもページメモリ内だけで、再読み込みすると消えます。
